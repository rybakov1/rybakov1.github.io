# DiagDoc

Русскоязычная платформа диагностических знаний: учебные алгоритмы, проверки, коды ошибок, симптомы, статьи и вымышленные практические случаи. В текущей версии это **локальное демо**, а не сервисная документация производителя и не полноценная диагностическая сессия. Значения, нормы и распиновки конкретного автомобиля необходимо сверять с документацией производителя.

## Запуск

Нужны Node.js 20.19 или новее и npm. Из папки `autodiag`:

```bash
npm install
npm run db:generate
npm run dev
```

Откройте адрес, указанный в терминале, обычно `http://localhost:3000`. Для просмотра каталога и работы с редактором база данных не требуется. Команда `db:generate` генерирует клиент Prisma для оставленной инфраструктуры базы данных; подключение к самой базе для этого не требуется.

Проверка содержимого прежнего справочника и сборка:

```bash
npm run content:check
npm run build
```

Результат статической сборки находится в `out/`. В режиме `output: 'export'` команда `next start` не обслуживает эту сборку; для локальной проверки можно запустить статический сервер, например:

```bash
python -m http.server 3000 --directory out
```

`NEXT_PUBLIC_SITE_URL` задаёт публичный домен для метаданных и карты сайта во время сборки. В GitHub Actions он установлен в `https://diagdoc.ru`; для другой среды задайте его до запуска `npm run build`.

## Возможности демо

- `/` — обзор и общий поиск по демо-материалам.
- `/codes/`, `/symptoms/` — коды и симптомы; `/references/?id=dtc:p0301` — пример карточки кода.
- `/algorithms/`, `/algorithms/view/?id=misfire-p0301` — каталог, граф и чтение шагов. Чтение не записывает результаты проверки.
- `/checks/`, `/checks/view/?id=codes` — библиотека методик; `/knowledge/`, `/cases/` — база знаний и вымышленные случаи.
- `/editor/` — визуальный редактор графа. Добавляйте шаги и переходы, сохраняйте черновик и публикуйте после проверки графа. Для редактирования своего черновика можно открыть `/editor/?id=...`.
- `/diagnosis/` — честная заглушка будущей диагностической сессии; `/settings/` — локальный демо-вход и выбор роли.
- Ранее созданные справочные страницы, например `/codes/p0420/`, сохранены.

Учебные примеры обозначены как демо и не OEM. Автомобили в примерах служат подписями применимости; VIN-декодера и заводских норм нет.

## Данные и демо-аккаунты

Вход на странице настроек — выбор одного из двух **локальных демо-профилей**, без регистрации, пароля и настоящей проверки личности. Роли `user` и `admin` показывают сценарии интерфейса и не являются защитой доступа. Авторы могут создавать и публиковать свои черновики, администратор — скрывать опубликованные материалы в своём браузере. Копирование создаёт отдельный черновик.

Локальное рабочее пространство хранится в `localStorage` текущего браузера. Нажатие «Опубликовать» делает алгоритм видимым в локальном каталоге **только на этом устройстве и в этом браузере**: данные не отправляются в GitHub, PostgreSQL или на сервер и не видны другим посетителям. При очистке данных браузера они могут быть потеряны. Демо-роль администратора не обеспечивает реальную авторизацию или модерацию.

Демо-набор находится в `src/platform/seed.ts`, типы — в `src/platform/models.ts`, локальное хранилище и операции — в `src/platform/store.tsx`, проверка графа — в `src/platform/graph.ts`. Публикация из интерфейса проверяет наличие стартового шага, достижимость, переходы, выходы и путь к заключению; эта проверка не подтверждает техническую достоверность диагностической методики.

Инфраструктура PostgreSQL/Prisma, Zod и импорта прежнего SEO-справочника остаётся в проекте, но **не является серверным хранилищем редактора**. Для старых записей подробные команды находятся в [CONTENT.md](CONTENT.md). Чтобы сделать настоящие общие аккаунты и публикацию для всех, нужны сервер, база данных, авторизация, контроль доступа и отдельное подключение редактора к API.

## Границы архитектуры

`Algorithm` — шаблон с версией и графом `AlgorithmGraph`. Граф содержит `schemaVersion`, стабильные ID узлов, стартовый узел и переходы с типизированными условиями. Координаты узлов используются только для отображения; они не задают диагностическую логику. Редактор хранит структуру алгоритма, но не результаты проверки конкретного автомобиля.

Типы будущих `DiagnosticSession`, `DiagnosticFact`, `Measurement`, `DiagnosticHypothesis` и `DiagnosticConclusion` описаны отдельно в `src/platform/models.ts`. Будущая сессия должна сохранять ссылку на конкретную опубликованную ревизию или неизменяемый снимок графа, чтобы правки шаблона не меняли историю. Интерфейсы ввода измерений, механизм гипотез и хранение сессий пока не реализованы.

## Публикация и ограничения

Проект использует Next.js App Router, TypeScript, Tailwind CSS, React Flow, Prisma, Zod и статический экспорт. GitHub Actions собирает `autodiag/out` и публикует его в GitHub Pages; там нет постоянно работающего Node-сервера и прямого подключения к PostgreSQL. Изменения кода и встроенного демо-набора становятся общедоступными после коммита и успешной сборки. Локальные черновики пользователя в эту публикацию не попадают.

Страницы с параметрами, представляющие локальные данные, не являются отдельными индексируемыми SEO-страницами. Существующие статические справочные URL, `robots.txt` и карта сайта сохранены. Индексация зависит от поисковой системы и не гарантируется сборкой сайта.

Следующая версия может добавить диагностические сессии с фактами и измерениями, повторное использование показаний, оценку гипотез, обоснованные заключения, отчёт, реальную учётную запись и синхронизацию, VIN-декодер и ИИ-помощника. Сейчас эти функции не выполняются.
