# Работа с материалами

Поставляемая подборка находится в `src/data/demo-content.ts` и имеет статус `needs_review`, потому что она ещё не прошла полноценную редакционную проверку. Демо-режим показывает её для оценки интерфейса и закрывает от поисковой индексации. До публичного запуска необходимо проверить материалы по источникам и документации производителей, отдельно утвердить каждую запись и только после этого изменить её статус на `published`.

Статический набор позволяет запустить интерфейс без базы данных. Изменения в базе попадают на сайт после явного экспорта и пересборки. `src/data/content.ts` объединяет демо с `src/data/published.json`; проверенная запись с тем же slug заменяет демонстрационную в интерфейсе, но исходный демо-файл не изменяется. Сам сайт пока остаётся демонстрационным и закрытым от индексации даже после экспорта. Не храните настоящий пароль в репозитории.

## Проверка и импорт

1. Скопируйте `.env.example` в `.env` и настройте `DATABASE_URL` для PostgreSQL.
2. Установите зависимости, затем выполните `npm run db:generate` и `npm run db:push`.
3. Проверьте материалы: `npm run content:check`. Проверка доступна и без запущенной базы.
4. Загрузите записи: `node --env-file=.env --import tsx scripts/import-content.ts`. Для этой команды нужен Node.js 20.6 или новее. Если `DATABASE_URL` уже передан в окружение, можно использовать `npm run content:import`. Импорт использует одну транзакцию и обновляет записи по типу и slug; отсутствующие в источнике записи он не удаляет.
5. После редакционной проверки и изменения статусов экспортируйте опубликованные записи: `node --env-file=.env --import tsx scripts/export-published.ts`, затем выполните `npm run build`. Если `DATABASE_URL` уже в окружении, достаточно `npx tsx scripts/export-published.ts`. Экспортирует только `published`; если любая запись не проходит валидацию, существующий файл экспорта не заменяется. Пустая база создаст пустой файл опубликованных материалов, не удаляя демо.
6. Для полнотекстового поиска в базе выполните `npx prisma db execute --file prisma/search-index.sql`. Функция `searchPublishedContent` в `src/lib/database-search.ts` ищет только опубликованные записи и поддерживает поиск по началу кода и русскоязычный полнотекстовый поиск. Интерфейс текущей статической версии ищет по экспортированному набору; подключение функции к страницам требует отдельной интеграции.

Можно загрузить JSON вместо демо: `node --env-file=.env --import tsx scripts/import-content.ts --file ./content.json`, а для проверки без импорта — `npm run content:check -- --file ./content.json`. Файл представляет объект с четырьмя массивами: `codes`, `symptoms`, `indicators`, `guides`; поля записей соответствуют `src/lib/content-schema.ts`.

## Редакционный контроль

Статусы: `draft`, `needs_review`, `published`. До публикации проверьте факты и укажите как минимум один доступный источник, дату проверки `verifiedAt` и `verificationStatus: "verified"`. Проверка структуры и наличия ссылок не устанавливает достоверность фактов автоматически. Валидатор также проверяет обязательные поля, даты, дубликаты URL и кодов, соответствие группы и кода, минимальную структуру опубликованных записей. Страницы с недостаточными данными не следует публиковать. Индивидуальная проверка источников остаётся задачей редактора.
