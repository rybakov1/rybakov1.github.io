# Подготовка MVP к запуску на VPS

Эта конфигурация предназначена для Linux-сервера с Docker Engine, Docker Compose v2 и Python 3. Она использует отдельный проект и отдельный том PostgreSQL `cenoscope-public_postgres-data`; локальная SQLite и данные другого Compose-проекта автоматически не переносятся. Сайт, API и база работают на одном сервере. Внешние порты только 80 и 443: Caddy получает и продлевает TLS-сертификат, Nginx направляет `/api/` в API, остальные страницы — в Astro.

Для запуска нужны VPS, домен с A/AAAA-записью на этот VPS, доступные извне TCP-порты 80 и 443 и достаточное место для базы и резервных копий. Если IPv6 не настроен, не добавляйте неработающую AAAA-запись. Домен должен быть настоящим, а не `example.com`. Исходный код и архив расширения нужно заранее скопировать на VPS своим обычным способом; не копируйте локальную `.env`, SQLite, `.venv` или `node_modules`.

## Настройка и запуск

Из корня проекта на сервере:

```bash
cp .env.public.example .env.public
chmod 600 .env.public
```

Откройте `.env.public` в редакторе. Укажите `SITE_DOMAIN` без протокола и пути. Создайте **два разных** случайных значения и запишите их отдельно в `POSTGRES_PASSWORD` и `ADMIN_TOKEN`:

```bash
python3 -c 'import secrets; print(secrets.token_hex(32))'
```

Выполните команду дважды. Не записывайте секреты в `PUBLIC_*`, не публикуйте `.env.public`, не передавайте токен через переписку или URL. Переменные окружения shell имеют приоритет над `--env-file`; удалите конфликтующие переменные `SITE_DOMAIN`, `POSTGRES_PASSWORD`, `ADMIN_TOKEN`, если preflight сообщит о них.

```bash
python3 scripts/public-preflight.py .env.public
docker compose --env-file .env.public -f docker-compose.public.yml up -d --build
docker compose --env-file .env.public -f docker-compose.public.yml ps
docker compose --env-file .env.public -f docker-compose.public.yml logs --tail 100 tls gateway backend frontend
```

Не выполняйте `docker compose config` в публичном терминале или чате: итоговая конфигурация может содержать секреты. Проверка preflight не проверяет доступность домена и портов; сертификат появится только после успешной проверки домена центром сертификации. При ошибке сертификата проверьте DNS, firewall и логи `tls`.

Проверьте в браузере `https://ваш-домен/` и `https://ваш-домен/api/config`: должно быть `data_mode: import`. Затем откройте `/import/`, введите `ADMIN_TOKEN` и загрузите свою выгрузку расширения. В `/admin/` можно указать категорию импортированной карточки; категория не подтверждает точное совпадение моделей. Новый публичный каталог пуст до загрузки реальных данных. `DEMO_MODE=false` задан в конфигурации явно, синтетический fallback отключён. Изменение существующего тома из другого проекта не выполняется.

## Перенос существующей локальной базы

Если нужно перенести не только новые выгрузки, а все ранее импортированные карточки, историю, подтверждённые модели и настройки модерации, используйте защищённый перенос **до первого импорта на VPS**. Он копирует все таблицы целиком, включая отключённые демозаписи (они останутся скрыты при `DEMO_MODE=false`). Запуски сбора, сохранённые подписки и служебные записи также войдут в файл. Перенос не копирует конфигурацию `.env` и ключи шифрования; при последующем включении Telegram сохраните его старый ключ отдельно, иначе старые зашифрованные подписки нельзя будет расшифровать.

На Windows в корне локального проекта сначала запустите и остановите проект, чтобы применить актуальные миграции, затем создайте новый файл в закрытом локальном каталоге:

```powershell
.\scripts\start-dev.ps1
.\scripts\stop-dev.ps1
New-Item -ItemType Directory -Force .local\transfer | Out-Null
.\backend\.venv\Scripts\python.exe .\scripts\transfer-database.py export --sqlite .\backend\cenoscope.db --output .\.local\transfer\cenoskop-db.ndjson
```

Файл содержит все данные базы, включая потенциально конфиденциальные служебные записи. Не отправляйте его в чат, не публикуйте и не добавляйте в Git. Скрипт читает SQLite в режиме только для чтения, берёт согласованный снимок и отказывается перезаписывать существующий файл. На Linux файл создаётся с правами 0600; на Windows проверьте права доступа к каталогу и файлу, поскольку используются разрешения учётной записи и каталога. При неудачном экспорте удалите частичный файл вручную перед повтором.

Создайте на VPS закрытый каталог (`install -d -m 700 ~/cenoskop-transfer`), перенесите файл по доверенному каналу, например SCP, и ограничьте его доступ (`chmod 600 ~/cenoskop-transfer/cenoskop-db.ndjson`). После обычного `docker compose ... up -d --build` дождитесь готовности API и из корня проекта на VPS выполните:

```bash
docker compose --env-file .env.public -f docker-compose.public.yml exec -T backend python /tools/transfer-database.py import < ~/cenoskop-transfer/cenoskop-db.ndjson
```

Пароль берётся из окружения контейнера и не передаётся в командной строке. Импорт проверяет ревизию миграций, таблицы, число строк и контрольную сумму; он работает одной транзакцией и отказывается изменять непустую базу. Источник и получатель должны иметь одинаковую ревизию Alembic. При ошибке или прерванной передаче данные не применяются. Контрольная сумма обнаруживает повреждение файла, но не подтверждает отправителя: передавайте файл по доверенному каналу. После проверки сайта удалите временные копии по своей политике хранения. Локальную исходную базу сохраняйте как резервную копию.

Перенос проверен на тестовых SQLite и read-only копии локальной базы; **реальный импорт в PostgreSQL ещё необходимо проверить на VPS**, так как в текущем окружении PostgreSQL/Docker недоступны. Перед использованием на работающей базе создайте отдельную резервную копию и проверьте восстановление на независимом стенде.

До наполнения и проверки страниц `PUBLIC_INDEXABLE=false`: сайт отдаёт `noindex`, `robots.txt` закрывает обход, sitemap пуст. После наполнения, проверки карточек, прав на содержимое и готовности к поисковой индексации можно изменить значение в `.env.public` на `PUBLIC_INDEXABLE=true`, повторить preflight и `docker compose --env-file .env.public -f docker-compose.public.yml up -d --build`. Проверьте метатег robots, `/robots.txt` и `/sitemap.xml` на работающем домене. Непроверенные карточки JSON сохраняют `noindex`, а sitemap включает только пригодные подтверждённые страницы с достаточной историей. Флаг управляет только индексацией и не делает сайт приватным.

Приложение использует собственный API для каталога и импорта; расширение продолжает работать через отдельные JSON-файлы, без API маркетплейсов. Сайт не собирает категории или историю автоматически: их создают повторные запуски сборщика и загрузки файлов. Загрузка новых данных не подтверждает сопоставление между маркетплейсами, условия оплаты или права на изображение.

## Ограничения и обслуживание

- Nginx ограничивает `/api/admin/` по клиентскому IP: 30 запросов в минуту, короткий всплеск до 15; при превышении возвращается 429. Это не замена длинному случайному токену и не блокировка конкретной учётной записи. Размер тела ограничен 6 МиБ на gateway и дополнительно контролируется API. Если перед VPS стоит внешний балансировщик, все запросы могут видеться с одного IP — настройку доверенных прокси нужно отдельно перепроверить.
- Caddy и Nginx соединены закрытой сетью `172.28.197.0/24`; Nginx доверяет переданному адресу клиента только от Caddy `172.28.197.2`. При пересечении этой подсети с сетью VPS надо согласованно изменить subnet/IP в Compose и `set_real_ip_from` в Nginx. Не публикуйте порт gateway и не подключайте к этой сети посторонние сервисы.
- Проверьте источник и условия использования фотографий, рейтингов и других данных для публичного сайта; сбор ссылки не подтверждает право её публиковать. Отдельные отзывы и история за периоды, которые ещё не наблюдались, не создаются автоматически.
- Telegram и прежний серверный контур сборщика отключены. История, выборка отзывов, сопоставление вариантов и полнота карточек зависят от реально накопленных наблюдений.
- Настройте резервные копии и проверьте восстановление на отдельном сервере. Пример создания дампа на Linux из корня проекта:

```bash
umask 077
mkdir -p backups
docker compose --env-file .env.public -f docker-compose.public.yml exec -T db pg_dump -U cenoscope -Fc cenoscope > backups/cenoscope.dump
```

Храните копии за пределами VPS с ограниченным доступом; простой `docker compose down` сохраняет том, а `down -v` удаляет базу и сертификаты. Для обновления кода повторите preflight и `up -d --build` после резервного копирования. `PUBLIC_*` встраиваются в Astro при сборке, поэтому изменение домена требует пересборки.

Эта конфигурация подготовлена в проекте, но в текущем окружении Docker/VPS не доступны: запуск контейнеров, выпуск сертификата, реальный импорт через публичный домен и проверка ограничений на рабочем сервере ещё требуются перед открытием сайта пользователям.
