# Автоматический сборщик — JSON без API

Текущая версия расширения — **0.6.0**. Значок открывает полноразмерную вкладку управления. Расширение самостоятельно обходит введённую очередь и выгружает JSON. Настраивать `COLLECTOR_TOKEN`, включать backend или создавать канонические модели для его работы не требуется.

Установка, настройки и ограничения описаны в [инструкции расширения](../browser-extension/README.md).

В нескольких независимых профилях установите расширение и задайте одинаковое число экземпляров и уникальные номера. Каждый профиль сканирует категории, обрабатывает назначенные товары и создаёт отдельный JSON. Инструкция находится в README расширения.

Настройки запуска можно копировать и редактировать как отдельный конфигурационный JSON `cenoskop.collector-config.v1`. Вставьте текст в блок «Конфигурация JSON», нажмите «Применить JSON», затем «Начать сбор». Этот документ содержит настройки, а не результаты; применение не продолжает и не запускает сбор автоматически. Пример и имена полей приведены в README расширения.

## Текущий поток

1. Пользователь указывает карточки и, при необходимости, категории Ozon.
2. После «Начать» браузер запрашивает доступ к выбранным площадкам.
3. Одна фоновая вкладка последовательно загружает страницы с паузами. Очередь и результаты сохраняются в локальном профиле.
4. В категориях Ozon выполняются ограниченные прокрутки с ожиданием подгрузки, накоплением уникальных ссылок и переходом по найденной ссылке «Далее». По умолчанию — 12 прокруток, 100 товаров на исходную категорию, до 3 страниц категории. Общий предел очереди отдельно ограничивает число товаров и страниц. JSON-LD и видимый DOM разбираются без скрытых API. Неоднозначные поля помечаются для проверки.
5. JSON скачивается по завершении, если настройка включена. Промежуточные данные можно выгрузить отдельно. При блокировке обход прекращается.

Кнопки «Показать JSON» и «Скопировать JSON» позволяют отправить текст в чат без скачивания. Это снимок текущего состояния: для обновления нажмите «Обновить JSON». Каждый профиль имеет свой отдельный JSON.

Расширение не пишет в сайт и БД. JSON содержит наблюдения, а не подтверждённые сопоставления канонических моделей. Для записи в основной каталог нужна отдельная проверка вариантов и условий цены.

## Добавить JSON в каталог сайта

Для общего каталога должны работать frontend и backend. В PowerShell из корня проекта: `./scripts/start-dev.ps1`. Затем откройте `http://localhost:3000/import/`, выберите выгрузку, введите `ADMIN_TOKEN` из локальной `.env` и нажмите **«Добавить в каталог сайта»**.

Все записи сохраняются на сервере и появляются в `http://localhost:3000/catalog/?source=uploaded`. Они помечены как непроверенные карточки: категория, модель, продавец, условия оплаты и другие отсутствующие факты не придумываются. У каждой ссылки есть отдельная страница с исходными полями и хронологией замеров. Рейтинги, медианы и автоматическое объединение с канонической моделью отключены. Повторный импорт того же файла не создаёт дубликаты; новые замеры той же ссылки добавляются к её истории.

Расширение по-прежнему работает без API. Только явная загрузка файла через сайт использует сервер сайта.

Из командной строки доступен тот же импорт с чтением ключа из `.env` без его вывода:

```powershell
python scripts/import-browser-json.py "C:/path/to/cenoskop-export.json"
```

Административный маршрут: `POST /api/admin/browser-import` с `content` и `filename`, Bearer `ADMIN_TOKEN`. Миграция `0003` создаёт отдельную таблицу `browser_snapshots`; канонические модели и их история не перезаписываются.

## Просмотреть JSON только в этом браузере

На той же странице можно выбрать «Сохранить для просмотра». Только это дополнительное действие сохраняет файл локально и не добавляет его в каталог. Для локального просмотра сервер API и ключ администратора не нужны.

Страница сохраняет файл в локальном хранилище текущего браузера для этого адреса сайта. Поддержаны поиск, подробности неизвестных полей, исходные ссылки, повторное скачивание и очистка. Исходный файл в «Загрузках» не изменяется. При следующем открытии на том же адресе данные восстанавливаются.

Локальный просмотр и серверный каталог — разные места хранения. Старый раздел админки «Импорт фида» ожидает полный формат; для объекта расширения пользуйтесь страницей «Импорт JSON» и основным действием добавления в каталог.

## Совместимость

Прежние `/api/collector/*` и административная очередь остаются в серверном проекте. Версия 0.4 их не вызывает. Переменные `COLLECTOR_*` относятся к прежнему серверному контуру и не требуются JSON-сборщику.

При обновлении расширение удаляет прежние настройки подключения и локальные ключи. Серверная `.env` не входит в ZIP. Для новой работы выбирайте **v0.6.0**. Прежние JSON формата v1 остаются совместимыми с импортом; новые файлы содержат также настройки и диагностику чтения категорий.
