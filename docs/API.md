# API и импорт

FastAPI публикует актуальный контракт на `http://localhost:8000/docs`, JSON OpenAPI — на `/openapi.json`. Это источник точных полей, ограничений и кодов ответов. Все суммы импортируемого MVP — положительные значения RUB; время наблюдения обязательно содержит часовой пояс и нормализуется в UTC.

## Публичные данные

Основные маршруты:

- `GET /health` — доступность API/БД и режим данных.
- `GET /api/config` — рабочее имя, режим и состояние Telegram.
- `GET /api/products` — поиск `q`, `category`, `brand`, `min_price`, `max_price`, `deals`, сортировка `sort`, пагинация `page`/`page_size` (не более 100).
- `GET /api/products/{slug}` — карточка с офферами и аналитикой.
- `GET /api/products/{slug}/history?days=7` — 7/30/90 календарных дней либо `days=0` для всего наблюдаемого периода; `offer_id` выбирает конкретный оффер.
- `GET /api/products/{slug}/reviews?slice=100` — `all`, `500`, `100`, `10`, `30d`, `90d`.
- `POST /api/alerts` — `{ "product_id": "…", "target_price": 10000, "consent": true }`, ожидающая подтверждения подписка. Число в примере — условный порог пользователя.
- `POST /api/events` — только событие `product_view` для существующего `product_id`.
- `GET /api/out/{offer_id}` — проверенный внешний переход; демо возвращает 409 вместо имитации покупки.

Каталог отдаёт канонические модели, карточка — совместимые офферы, историю и рассчитанные показатели. Данные содержат `is_demo`/`data_provenance`; фронтенд должен сохранить эту маркировку. Даты первой/последней точки относятся к доступному периоду. Срезы отзывов доступны только в пределах имеющихся данных одного варианта. Не выдумывайте данные при `null`.

Служебная конфигурация сообщает, включён ли Telegram. При отсутствии токена/имени/ключа шифрования сайт остаётся работоспособным, но не должен показывать фиктивно созданную активную подписку.

## Авторизация администратора

Админские операции требуют `Authorization: Bearer <ADMIN_TOKEN>`. Токен задаётся только серверным окружением. Пустой токен отключает административный доступ. Не передавайте секрет в URL, публичные build-переменные или репозиторий. Операции включают просмотр источников/запусков/ошибок, импорт разрешённого фида, управление видимостью товаров и модерацию спорных совпадений.

- `GET /api/admin/status` — источники, последние запуски, счётчики и состояние бота.
- `GET /api/admin/products` и `PATCH /api/admin/products/{product_id}` с `{ "active": false }` — список и видимость модели.
- `POST /api/admin/products` — каноническая модель с `name`, `brand`, `model`, `category`, `capacity`, `bundle`, `condition`, при наличии `mpn`, `gtin`, `specs`. Это метаданные без офферов и вымышленных цен.
- `GET /api/admin/matches` и `POST /api/admin/matches/{match_id}` с `{ "decision": "approve" }` либо `reject` — очередь проверки.
- `POST /api/admin/import` — `{ "source_id": "feed-id", "permission_reference": "Contract reference", "format": "csv", "content": "…" }`. `format` также может быть `json`; `content` содержит текст файла, а не URL.

## Контракт CSV/JSON

Импортёр принимает JSON-массив объектов или CSV с заголовком, UTF-8 (поддерживается BOM). Лимит одной порции — 5 MB и 10 000 строк. Неизвестные поля отклоняются. Сначала валидируется вся порция; не загружайте файл с произвольной схемой.

Обязательные поля каждой строки:

- `external_id` — стабильный ID конкретного предложения внутри источника, а не общий ID канонической модели;
- `brand`, `model`, `mpn` (может быть пустым, если неизвестен), `category` (`ssd`, `ram`, `gpu`), `capacity`, `bundle`, `condition` (`new`, `used`, `refurbished`, `unknown`);
- `seller_id`, `seller_name`, `marketplace`;
- `price`, `region`, `payment_condition`, `availability`, `observed_at`, `url`.

Дополнительно: `gtin`, `currency` (по умолчанию `RUB`), `price_type` (`regular`, `membership`, `installment`, по умолчанию `regular`), `warranty_months` (0–240 либо отсутствие данных). В CSV отсутствие необязательного поля лучше обозначить отсутствующим столбцом; не подставляйте текст `null` в числовое поле. Для сложных отсутствующих значений используйте JSON.

`observed_at` содержит ISO 8601 с `Z`/смещением. Дата в будущем более чем на 10 минут отклоняется. `url` должен быть HTTPS, без credentials и нестандартного порта, с точным разрешённым hostname из `ALLOWED_OUTBOUND_HOSTS`. Разрешение URL не является разрешением сбора данных. Импортёр не запрашивает этот URL.

Контекст сопоставимой истории модели закрепляется первым реальным предложением и возвращается как `price_context`. Другие регион, тип цены и оплата остаются отдельными офферами и не смешиваются с этой историей. В синтетическом демокаталоге используется `RUB / RU-MOW / regular / any_card`. Регион реального наблюдения задаётся явно, не выводится из адреса сервера или низкой цены.

Каждый запуск требует `source_id` (не `demo`) и текстовую ссылку на действительное разрешение/договор минимум из 8 символов. Происхождение хранит заявление оператора отдельно от фотографий/отзывов, которые этот импорт не загружает. У реальных импортированных моделей рейтинги и детальные отзывы остаются недоступны, если источник их не предоставил.

CLI из `backend/`:

```powershell
python -m app.import_feed examples/import.csv --source-id permitted-feed --permission 'Reference to signed data agreement'
```

Сначала примените миграции и задайте `DATABASE_URL`. Повтор одного наблюдения с тем же предложением, временем, валютой, регионом, типом цены и оплатой считается дубликатом. Отчёт содержит `run_id`, `imported`, `duplicates`, `pending_matches`. Подозрительные совпадения попадают в очередь проверки, а не бесконтрольно объединяются.

## Безопасные переходы и аналитика

Внешний переход выполняется по известному `offer_id`, а не по произвольному параметру `url`. Сервер проверяет сохранённый URL по whitelist; это защищает от открытого редиректа. Для демопредложений нет реального оффера для покупки. Переходы не должны имитироваться при рендеринге или предварительной загрузке страницы.

События просмотра карточки, настоящего перехода и создания алерта минимальны: продукт/оффер, тип, дата. Для таких событий не нужен текст поисковых запросов, IP, Telegram-профиль или содержимое сообщений. Сервер не обещает партнёрскую комиссию: URL обычные, пока не подключён действительный разрешённый партнёрский оффер.

## Алерты

Создание намерения отслеживания не равно подписке без согласия. API выдаёт deep link с непредсказуемым одноразовым подтверждением; активирует уведомления сам пользователь в личном боте. Telegram ID хранится защищённо и не возвращается публичному клиенту. Бот показывает список/отмену, worker повторно проверяет цену, применяет fingerprint-дедупликацию и cooldown 24 часа. Запускайте один worker: доставка имеет семантику at-least-once, при аварии между успешной отправкой Telegram и фиксацией результата в БД возможен повтор. Атомарной транзакции между Bot API и локальной БД нет. Команды: `/list`, `/cancel ID`, `/stop`. Неподтверждённый deep link истекает через 24 часа.

## Очередь браузерного сбора

У администратора: `GET /api/admin/collector/status`, `GET /api/admin/collector/jobs`, `POST /api/admin/collector/jobs`. Создание задания принимает `product_id`, прямой `url` карточки, `marketplace` (`ozon`/`wildberries`) и `permission_reference`. Состояния: `queued`, `leased`, `completed`, `failed`. Сервер не загружает переданный URL.

Расширение использует отдельный `Authorization: Bearer <COLLECTOR_TOKEN>`:

- `GET /api/collector/config`, `GET /api/collector/products` — состояние и канонические варианты;
- `POST /api/collector/jobs/claim` с `worker_id` — аренда следующего задания; `job:null` означает пустую очередь;
- `POST /api/collector/jobs/{job_id}/fail` с `worker_id`, `lease_token` и кодом ошибки — отказ от полученного задания;
- `POST /api/collector/observations` — подтверждённые поля, время, URL, выбранная модель и происхождение. Для задания также требуются совпадающие `job_id`/`lease_token`. Неподтверждённый вариант, чужая/истёкшая аренда и попытка изменить уже завершённое наблюдение отклоняются.

Полная схема наблюдения/код ошибок — в OpenAPI. Настройки `COLLECTOR_ENABLED`, `COLLECTOR_TOKEN`, `COLLECTOR_PERMISSION_REFERENCE`, `COLLECTOR_LEASE_SECONDS` доступны только серверу. Сбор не включается при отсутствии обязательных настроек. Секрет не публикуется в админском статусе. Практический процесс — в [инструкции расширения и очереди](BROWSER_COLLECTOR.md).
