# Локальный формат наблюдений v1

Файл имеет `schema_version: "cenoskop.browser-export.v1"` и четыре верхних поля: `schema_version`, `job`, `observations`, `errors`. Машиночитаемое описание — [`export-schema.json`](export-schema.json). Это файл фактов с открытых страниц и диагностикой прохода; автоматическое сопоставление с моделью каталога не выполняется.

`job` содержит идентификатор локального прохода, статус, признак неполного результата, время начала/обновления/экспорта, настройки задержек и лимитов, ограниченную очередь, число обработанных страниц, найденных и отброшенных ссылок. `partial: true` означает, что проход ещё не завершён либо остановлен. `truncated_count` сообщает о ссылках, не добавленных из-за лимитов.

С версии расширения 0.3 `settings` может дополнительно содержать `categoryScrollRounds` (0–50), `categoryScrollPauseSeconds` (1–10), `categoryMaxProducts` (1–200), `categoryMaxPages` (1–10). Во время чтения категории сборщик прокручивает видимую страницу и накапливает уникальные SKU; следующую страницу открывает лишь по явной ссылке DOM внутри той же категории. URL очереди категории допускает только дополнительный `?page=2..1000`.

У элементов категории в `queue` может присутствовать `discovery`: `rounds` — число чтений, `scrolls` — число прокруток, `found_count` — накопленное число найденных карточек, `page_number` — порядковая страница исходной категории. `stop_reason` — `round_limit`, `product_limit`, `queue_limit`, `end`, `no_growth` либо `null` для незаконченного чтения. Внутренние списки ссылок и состояние прокрутки не экспортируются. Эти новые поля необязательны: файлы версии 0.2 продолжают импортироваться.

Каждый элемент `observations` создаётся чистой функцией `CenoskopExtractor.buildObservation(capture, {requested_url})`:

- `source`: площадка, каноническая ссылка по SKU, исходно запрошенная каноническая ссылка при наличии, метод (`jsonld`, `dom`, `none`), версия экстрактора и время наблюдения.
- `product`: буквальное название, бренд, модель, MPN, SKU площадки, объём, комплектность и состояние. Неизвестные строковые факты — `null`; неподтверждённое состояние — `unknown`. Объём из названия извлекается лишь при единственном явно указанном значении. Названия похожих товаров и суффиксы Ti/Super не сопоставляются автоматически.
- `offer`: выбранная цена и валюта, регион, тип цены, условие оплаты, доступность, известные идентификатор/имя продавца и срок гарантии. `evidence` содержит только название города и короткий фрагмент ценового условия; адрес доставки не экспортируется.
- `candidates`: до 30 ограниченных кандидатов цены с методом, исходной суммой, короткой подписью, признаком совпадения JSON-LD с текущей страницей и известным продавцом. Это варианты для проверки, а не несколько автоматически сравнимых предложений.
- `needs_review`, `review_reasons`: наличие и причины неопределённости. `identity_confirmed` всегда `false`: расширение не подтверждает точное совпадение производителя, варианта и канонической модели.

Автоматически выбирается один конкретный JSON-LD `Offer` в RUB, если его Product совпадает с SKU/URL текущей страницы. Несовпадающие рекомендации из JSON-LD отбрасываются. Несколько конкретных совпавших предложений остаются неоднозначными, даже если суммы одинаковы. `AggregateOffer.lowPrice/highPrice` не становятся ценой покупки. Если единственного подходящего JSON-LD нет, общая цена из DOM остаётся `null`. Исключение — единственная точная цена с однозначной подписью обычной оплаты в проверенном текущем виджете `webPrice`; она всё равно помечается `dom_price_requires_review`.

Сумма сама по себе не определяет условия. Для поставленной структуры Ozon `330825 ₽ С банками … 367583 ₽ С другими банками` сумма 367583 соответствует `price_type: regular`, `payment_condition: other_bank_card` только при совпадении суммы и видимой подписи. При отсутствии подписи эти поля — `null`, даже если JSON-LD содержит цену. Регион распознаётся лишь в явных виджетах местоположения/доставки: пока поддержаны Москва (`RU-MOW`) и Санкт-Петербург (`RU-SPE`). Упоминание города в отзывах, описании или произвольном тексте страницы не используется. Полный адрес не сохраняется.

Продавец извлекается из совпавшего JSON-LD либо проверенного виджета текущего товара `webStickyProducts`; произвольные `/seller/` ссылки рекомендаций игнорируются. Отсутствующие продавец, MPN, состояние, гарантия и доступность не подменяются догадками. Гарантия в месяцах выводится только из точной строки вроде `1 год` или `24 месяца`; неоднозначные обещания остаются `null`.

При неоднозначности цена может быть `null`, а кандидаты останутся в файле. `source.extraction_method: none` означает, что однозначный кандидат не выбран и DOM-цены отсутствуют. CAPTCHA и ошибки страниц попадают в `errors`; обхода ограничений нет. Неполные строки пригодны для ручного анализа, но требуют проверки перед загрузкой в аналитическую историю.

С версии 0.4 наблюдение может содержать `images` (до 10 проверенных HTTPS ссылок), `specifications` (до 40 пар название/значение) и `rating` (оценка, количество оценок и отзывов и область). Неизвестные значения остаются null. Файлы изображений в JSON не включаются. Старые файлы без этих полей совместимы. Экспорт не содержит HTML, cookies, паролей, описаний и текстов отзывов. Агрегированный рейтинг JSON-LD не превращается в отдельные отзывы или динамику качества. Число заполненных полей не является оценкой надёжности продавца, подлинности товара или юридическим подтверждением прав на данные.
